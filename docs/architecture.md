# Устройство проекта

Источник текущей версии — `configuration/Configuration.xml` и корневой README:
«МолочнаяФерма», 1.2.7, управляемое приложение, русский язык, совместимость 8.3.27.
Учебная поставка рассчитана на 8.3.27.1688. Это учёт продукции, покупок, продаж и брони.

В `УчетФермы.ЗаблокироватьУчет` оба регистра накопления блокируются в одном порядке.
Изменения проведения должны учитывать проверки продажи по брони и транзакции.
Это выборочное обследование точек входа, а не полный аудит бизнес-логики.

## Решения и источники истины
- Актуальная реализация — выгрузка `configuration/`; шаблоны не гарантируют полного
  воспроизведения текущей выгрузки. Например, `wire_embedded_tests.py` переносит
  тестовый код из `scripts/bsl` в общий модуль и форму; правки этих участков согласовывать.
- `build_configuration.py` создаёт первоначальный выпуск 1.0.0; исторические генераторы
  и `platform_step.py` содержат старые версии и macOS-пути. Не использовать как
  универсальную сборку 1.2.7.
- `reservation_extension.py`/`extend_configuration.py` дорабатывают основную конфигурацию.
  Отдельных исходников расширений и `.cfe` при обследовании не найдено.
- Стек: 1С/BSL/XML, Python; OneScript runtime и `.os` не обнаружены.
  Vanessa Single 1.2.043.45: начальный UI-набор в tests/vanessa/ поверх существующих BSL-проверок; запуск и изоляция — docs/vanessa.md.
- Для навигации используется локальная Serena с BSL LSP. Graphify не применяется.
- README остаётся источником инструкции установки поставки и ссылок на актуальные
  материалы. Здесь — карта разработки; docs/testing.md — команды и ограничения;
  docs/status.md — состояние работ. Память Serena содержит только указатели.

Исторические [Сборка](../Документация/06_Технические_материалы/Сборка.md) и
[Тестирование](../Документация/06_Технические_материалы/Тестирование.md) полезны для
происхождения решений, но описывают 1.2.2 и 1.2.0 соответственно, не текущую сборку.

## Vanessa из интерфейса
Форма Автотесты (и её шаблон scripts/bsl/ВстроенныеАвтотестыФорма.bsl) содержит
native кнопку запуска и отдельный статус Vanessa. Локальный профиль возле файла базы
задаёт вспомогательный Python runner; каждый прогон создаёт другие изолированные базы.
Статус возвращается в форму через уникальный JSON. Развёртывание, подтверждённый
UI-результат и ограничения — docs/vanessa.md и docs/status.md.

## Фикстуры прямых Vanessa-сценариев
СервисФермы содержит подготовку, контроль и очистку VA04–VA06; шаблон —
scripts/bsl/ПрямыеСценарииVanessa.bsl, подключён в wire_embedded_tests.py.
Параметры запуска FarmVanessaPrepare/FarmVanessaCleanup обрабатываются до обычного
старта приложения и проверяют маркер пути отдельной базы. Только в такой базе
форма Автотесты добавляет контрольные поля для чтения регистров. Проверяемые
операции выполняются из feature через кнопки документов; общий модуль готовит
черновики/предусловия и читает результат, не заменяет действия UI-сценария.

Таблица Vanessa: реквизит формы `РезультатVanessa` (ТабличныйДокумент), динамическое
поле `ПротоколVanessa`, методы `ОписанияСценариевVanessa`/`ПоказатьТаблицуVanessa`.
BSL-шаблон и XML-шаблон wire_embedded_tests согласованы без запуска генератора.
`scenario_results` runner переносит отдельные результаты JUnit, включая ошибки
и пропуски, через JSON в серверную часть формы; на клиент передаются структуры.

VA07–VA10 используют тот же защищённый протокол фикстур: семь отдельных наборов
VA04–VA10. Для VA06–VA10 заранее проведены приход75 и бронь20; для VA09 дополнительно
записана новая бронь56. Проверяемые повторные проведения и отмены выполняет UI.
Контрольные кнопки и таблица формы расширены до VA10, runner требует10 результатов.

VA11–VA14 расширяют протокол до11 наборов фикстур VA04–VA14. VA11 имеет второй
черновик продажи по той же брони20; первая продажа выполняется UI. VA14 имеет
приход75 и непроведённую бронь со вчерашним сроком. VA12/VA13 используют обычные
75/20/55. Таблица/контроль формы расширены доVA14; бизнес-правила проведения не менялись.

VA15–VA18:15 наборов фикстур VA04–VA18. VA15 начинает с нулевыми остатками,
VA16–VA18 — с75/20/55. Runner готовит учебных пользователей и три профиля
TestClient с разными портами. Проверки прав выполняются в рабочих сеансах.
Три формы отчётов используют scripts/bsl/КонтрольОтчетовVanessa.bsl: только при
наличии fixture-файла добавляются скалярные поля, читающие ячейки уже сформированного
РезультатОтчета и реальные права текущего сеанса без повышения привилегий.
Шаблон двух исторически генерируемых отчётов ui_forms.py согласован; его запрос
остатков согласован с текущими колонками остатка/резерва/доступности.

Служебные элементы формы Автотесты помещены в динамическую обычную группу
СлужебныеДанныеVanessa с поведением Свертываемая. Начальное сворачивание выполняет
клиентский ПриОткрытии через Скрыть(); XML-атрибутов/прав не добавлялось.
Кнопки сгруппированы по три, подписи отделены от прежних значений Контроль…,
ВыбранныйСценарийVanessa показывает источник чисел. BSL-шаблон согласован;
feature разворачивают группу штатным шагом Vanessa перед чтением данных.
